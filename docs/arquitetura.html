ClinicaFácil— Diagrama de Arquitetura do Sistema

⬡ Frontend Vue 3

  • Views: Login, Registro, Dashboard, Agendamentos, Perfil, Admin
  • Sidebar com navegação e controle de perfil
  • Pinia Store para estado de autenticação global
  • Vue Router com guardas de navegação (beforeEach)
  • Axios com interceptor JWT automático
  • Busca de CEP ao digitar (ViaCEP via backend)
  • Grid de horários disponíveis em tempo real
  • Alerta de chuva integrado ao formulário de agendamento

⬡ Backend Node.js

  • Express com estrutura MVC (routes → controllers → models)
  • 4 grupos de rotas: auth, agendamentos, external, admin
  • express-validator para validação de entrada
  • express-rate-limit: 100 req/15min por IP
  • Middleware autorizar() por perfil (paciente/secretario/admin)
  • Índice único: médico + data + horário (evita conflitos)
  • Integração com ViaCEP e OpenWeatherMap
  • Exporta app separado do listen (testabilidade)

⬡ Banco de Dados MongoDB

  • Collection usuarios: nome, email, senha (hash), perfil, endereco
  • Collection agendamentos: paciente (ref), medico, data, horario, status
  • Subdocumento previsaoClimatica no agendamento
  • Índice composto único (medico + data + horario)
  • Mongoose ODM com hooks pre-save para hash de senha
  • Timestamps automáticos em todos os documentos

🔒 Autenticação JWT

  • Tokens JWT com expiração de 7 dias (configurável)
  • Senhas hasheadas com bcrypt, salt rounds = 12
  • Middleware autenticar() verifica token em todas as rotas protegidas
  • Middleware autorizar(...perfis) verifica permissão por perfil
  • Token enviado no header Authorization: Bearer <token>
  • Interceptor Axios injeta token automaticamente
  • Remoção automática do campo senha no toJSON()

🌤 APIs Externas Integração

  • ViaCEP: GET https://viacep.com.br/ws/{cep}/json/ — sem autenticação
  • OpenWeatherMap: /forecast?q={cidade}&appid={key} — 5 dias
  • climaService.js encontra previsão mais próxima da data da consulta
  • Campo temChuva detecta: Rain, Drizzle, Thunderstorm
  • Alerta de chuva retornado no POST /agendamentos
  • Falha silenciosa: se API indisponível, agendamento continua

🐳 DevOps Docker

  • Dockerfile backend: node:18-alpine, usuário não-root
  • Dockerfile frontend: build multi-stage com Nginx
  • docker-compose.yml: mongo + backend + frontend
  • Health check automático no container MongoDB
  • Volume persistente para dados do MongoDB
  • Nginx como proxy reverso para o backend
  • Testes automatizados com Jest + Supertest + mongodb-memory-server

Fluxo de Agendamento com Clima

01
Usuário autentica
POST /auth/login → recebe JWT → armazenado no Pinia Store
→
02
Seleciona médico e data
GET /horarios-disponiveis → backend consulta MongoDB → retorna slots livres
→
03
Busca previsão
GET /external/clima → backend chama OpenWeatherMap → retorna temChuva
→
04
Confirma agendamento
POST /agendamentos → valida horário → salva no MongoDB com clima
→
05
Alerta exibido
Se temChuva = true → frontend exibe aviso ⚠️ para o paciente
